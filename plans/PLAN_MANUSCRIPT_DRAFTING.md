## 1. 의미: 왜 이 단계가 필요한가

fig-atlas의 단계 스킬은 데이터 들이기(`ingest_plot`) → 스토리라인(`paper_storyline`) → 그림 합성(`assemble_figure`)까지 있다. 이 단계를 거친 연구 저장소에는 원고의 재료가 이미 구조화되어 있다.

- 스토리라인으로 승격된 본문·보충 그림과 그 순서(`storyline.yaml`)
- 그림마다 FigureSpec의 `panel_notes`(패널이 보여 주는 것)와 `claim_boundary`(그림이 말할 수 있는 범위)
- 데이터에서 기록된 수치(`claims.record`)와 검정 표(`stats.record`)
- 데이터 요청과 스토리라인 개정 기록(`fa storyline evidence`)

빠져 있는 것은 이 재료에서 **본문**으로 넘어가는 마지막 단계다. 지금은 legend의 숫자까지만 데이터와 이어져 있고, 본문의 숫자·그림 인용·주장의 강도는 사람의 기억에 맡겨져 있다. 이 계획은 그 연결을 본문까지 넓힌다.

## 2. 방향

1. **재료에서 시작한다.** 원고는 빈 문서가 아니라 스토리라인과 FigureSpec에서 시작한다. Results 개요의 뼈대(그림 순서, 소제목 자리, 패널 설명, 주장 한계)는 저장소에서 나온다.
2. **쓰는 순서를 안내한다.** Results → Discussion → Introduction → Methods → Abstract. 문단마다 *주장 한 문장 · 근거 패널 · 필요한 참고문헌의 역할 · 주장의 한계*를 적는 개요를 먼저 쓰고, 그 위에 문장을 올린다.
3. **확인할 수 있는 것만 도구로 만든다.** 본문 수치가 데이터에서 오는가, 모든 패널이 인용되는가, 인용 문헌이 실재하는가, 문장에서 데이터까지 따라갈 수 있는가. 논지·문제 설정·해석은 도구의 대상이 아니다.
4. **파일럿으로 키운다.** 실제 원고 하나(비공개 연구 저장소)에서 규약을 먼저 쓰고, 반복되는 수작업이 확인된 것만 도구로 만든 뒤, 일반 부분을 패키지로 옮긴다.

## 3. 범위

| 패키지·스킬이 하는 일 | 하지 않는 일 |
|---|---|
| 스토리라인·FigureSpec에서 개요 뼈대를 만든다 | 논지·Introduction의 문제 설정·Discussion의 해석을 정하지 않는다 |
| 본문의 `{name}` 자리를 claim 값으로 채우고, 손으로 친 결과 숫자를 센다 | 문장을 자동으로 생성하지 않는다(에이전트가 쓰는 초안은 §4 G2를 따른다) |
| 그림·패널 인용 누락과 없는 패널 인용을 찾는다 | 참고문헌을 고르지 않는다 |
| 인용 키가 `.bib`에 있고 DOI/PMID가 실재하는지 확인한다 | 문헌 내용이 주장을 뒷받침하는지 판정하지 않는다(사람이 읽는다) |
| 문장 → 그림 → 데이터 → 요청 기록을 따라간다 | 저널 서식 변환·제출 시스템 연동 |
| 작성 순서와 점검 항목을 스킬로 안내한다 | |

## 4. 가드레일

어기면 작업을 멈추고 연구자에게 보고한다.

- **G1 저자가 책임진다.** 원고의 모든 문장은 저자가 쓰거나 읽고 승인한다. 스킬은 순서와 점검을 안내할 뿐 원고를 "완성"하지 않는다.
- **G2 에이전트 초안은 표시한다.** 연구자가 요청해 에이전트가 쓴 문단은 표시(예: `<!-- draft: agent YYYY-MM-DD -->`)를 남기고, 저자가 검토하면 지운다. 투고 시 저널의 AI 사용 공개 규정을 따른다.
- **G3 기억으로 인용하지 않는다.** 에이전트가 제안하는 문헌은 *후보*다. DOI 또는 PMID로 실재와 서지 정보를 확인하기 전에는 `.bib`과 본문에 넣지 않는다. 확인하지 못한 후보는 `unverified`로 남긴다.
- **G4 결과 숫자는 데이터에서만.** 본문의 결과 수치는 claim(`{name}`)으로 쓰고 손으로 치지 않는다(`AGENTS.md` §4.5의 본문 확장). 임계값·설계값·그림 번호는 예외다.
- **G5 주장은 `claim_boundary` 안에서.** 본문 문장은 해당 그림의 `claim_boundary`보다 강하게 말하지 않는다. 예측 결과는 "예측되었다"로, 소표본 검정은 검정력 한계와 함께 쓴다. 넘는 문장은 저자 검토 항목으로 올린다.
- **G6 공개와 비공개를 나눈다.** 원고, 파일럿 기록, 연구 내용은 연구 저장소(비공개)에 둔다. fig-atlas(공개)에는 일반 부분만 옮기고, 예시는 가상 데이터로 만든다. 옮기기 전에 내용과 커밋 이력을 검사한다.
- **G7 도구는 마찰이 확인된 뒤에.** 파일럿에서 반복된 수작업으로 기록된 것만 Phase 3 카드가 된다. 짐작으로 만들지 않는다.
- **G8 원고 변경은 기록한다.** 원고 파일의 변경은 이유와 근거를 변경 기록에 남긴다(`AGENTS.md` §6과 같은 형식). 커밋은 연구자가 요청할 때만.
- **G9 방법 논문 범위를 지킨다.** 이 단계는 측정값이 나왔을 때만 fig-atlas 방법 논문의 결과가 된다(게이트 M4). 그 전에는 향후 과제로만 언급하고, 방법 논문의 투고 일정을 파일럿 원고에 묶지 않는다.

## 5. 추진 체계

**역할**

| 누구 | 하는 일 |
|---|---|
| 연구자(저자) | 게이트 결정, 원고의 논지와 문장, 문헌 판단, 카드 승인 |
| 에이전트 | 카드 수행: 뼈대 생성, 점검 실행, 문헌 후보 제시와 확인, 마찰 기록 정리 |
| 파일럿 저장소(비공개) | 원고, 스킬 초안, 마찰 기록, 측정 원자료 |
| fig-atlas(공개) | 이 계획과 상태 파일, 검증된 일반 부분 |

**흐름**

```
파일럿 규약(Phase 1) → 원고를 쓰며 마찰 기록 → 기준선 측정(Phase 2)
   → 게이트 M2: 만들 도구 선정 → 카드 구현(Phase 3) → 파일럿에 다시 적용
   → 게이트 M3: 일반 부분 이전(Phase 4) → 재측정, 게이트 M4(Phase 5)
```

**게이트 (연구자 결정)**

| 게이트 | 결정할 것 |
|---|---|
| M1 | 파일럿 규약: 원고 폴더 위치, 저널 계열(소제목 형식·Methods 위치), 개요 템플릿 |
| M2 | Phase 3에서 만들 도구(마찰 기록과 기준선에 근거) |
| M3 | 패키지로 옮길 범위와 공개 검사 통과 |
| M4 | 방법 논문에 결과로 넣을지, 향후 과제로 둘지 |

## 6. 측정 지표 (파일럿에서 정의대로 센다)

| 지표 | 정의 | 시점 |
|---|---|---|
| 손으로 친 결과 숫자 | 본문에서 claim이 아닌 결과 수치의 개수 | 기준선(도구 전 초안), 도구 후 |
| 인용되지 않은 패널 | 스토리라인의 패널 중 본문에서 인용되지 않은 수 | 기준선, 도구 후 |
| 없는 패널 인용 | 본문이 인용했으나 그림에 없는 패널 수 | 기준선, 도구 후 |
| 확인되지 않은 문헌 | DOI/PMID 확인이 안 된 인용 수(에이전트 후보 중 실재하지 않은 수 포함) | 문헌 단계마다 |
| 데이터 변경 후 수정 | 데이터가 바뀐 뒤 본문에서 손으로 고친 숫자 수 | 개정 시 |

측정 원자료는 파일럿 저장소에 두고, 이 계획에는 집계만 적는다.

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| 도구 만들기가 원고 작성을 밀어낸다 | G7: 마찰이 확인된 것만, Phase 3 카드 하나씩 |
| 파일럿 원고의 연구 내용이 공개 저장소로 샌다 | G6: 이전 전 내용·이력 검사, 예시는 가상 데이터 |
| 에이전트가 없는 문헌을 만든다 | G3: 확인 전에는 후보, 지표로 센다 |
| 본문이 그림보다 강하게 말한다 | G5: `claim_boundary` 대조를 점검 항목으로 |
| 방법 논문 일정이 파일럿에 묶인다 | G9: M4 전에는 향후 과제로만 |
| 한 원고에만 맞는 규약이 된다 | Phase 4 전에 가상 예시 원고로 다시 확인 |
