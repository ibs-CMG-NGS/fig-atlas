## 1. 배경과 목표

### 왜 지금인가

등록된 렌더러 가운데 **일반 표 렌더러가 없다**. 그런데 표를 그리는 코드는 이미 세 군데에서 손으로 쓰였다.

| 위치 | 형태 | 성격 |
|---|---|---|
| `fig_atlas/tools/compile_storyline_pdf.py` | 컴펜디움 표지의 그림 배정표. 줄바꿈 함수 2개, 동적 행 높이, 열 너비 상수 — 약 80줄 | 도구 안에 묻힘 |
| `fig_atlas_omics/renderers/motif_table.py` | 서열 로고가 붙은 표 | 분야 전용 |
| 연구 저장소의 분석 스크립트 | 검사 설계표를 `col_x`·`row_step`으로 손 배치 | 프로젝트마다 재작성 |

ADR 0003("렌더러는 분야가 아니라 모양")에 따르면 **표는 막대그래프만큼 일반적인 모양이고 코어에 있어야 한다**. 같은 코드를 세 번 썼다는 것은 자산이 빠져 있다는 신호다(AGENTS.md §3).

### 목표

1. CSV/DataFrame을 받아 **출판 관행의 표**를 최종 인쇄 크기로 그리고 벡터(PDF/SVG)로 낸다.
2. 그 표가 fig-atlas의 보장을 그대로 갖는다 — 설정이 정본, 인쇄 크기 1:1, preflight(글자 잘림·최소 글자 크기), 출처 기록.
3. 컴펜디움이 자족적이 된다. 지금은 그림만 페이지가 있고 표는 CSV로만 있어서, 내부 검토용 문서인데 표를 볼 수 없다.

### 하지 않는 것

- **저널 투고용 표를 대체하지 않는다.** 대부분의 저널은 표를 편집 가능한 텍스트(Word/Excel)로 받는다. 표를 이미지로 내면 교정·조판이 막히고 접근성이 떨어져 투고에는 **오히려 나쁘다**. 투고 경로는 CSV/Word 그대로 둔다. 이 렌더러의 쓸 곳은 컴펜디움·발표·포스터다.
- **긴 표를 그리지 않는다.** 수천 행짜리 전체 결과표(예: 유전자 전수 표)는 어떤 조판으로도 페이지에 들어가지 않는다. 대상은 **요약표**다. 행 선택·상한을 설정으로 두되, 상한을 넘으면 경고하고 자른다. 전수 표는 CSV로 남는다.
- **대화형 편집.** 고치는 길은 config 하나다.
- **표 안의 통계 계산.** ADR 0007과 같다. 표가 인쇄하는 값은 분석 스크립트가 만들어 컬럼으로 넣는다.

## 2. 원칙

1. **모양이지 분야가 아니다.** `fig_atlas/renderers/table.py`, 코어. 분야별 열 이름·기본값이 필요하면 레시피로 둔다.
2. **설정이 정본.** 보이는 모든 값은 SCHEMA에 선언한다. 하드코딩 금지(`fa lint --hardcoded --check`).
3. **열별 서식이 핵심이다.** 표가 전문적으로 보이느냐를 가르는 것은 레이아웃이 아니라 열별 정렬과 숫자 서식이다. 이것이 없으면 한 표 안에 `0.4871234`와 `41`이 섞인다. §3의 스키마에서 가장 먼저 설계한다.
4. **외관은 프리셋으로 가른다.** 출판 관행(`table_classic`)과 지금 컴펜디움 표지의 대시보드 외관은 **다른 프리셋**이다. 표지 코드는 돌아가고 테스트도 통과하므로 이 계획에서 건드리지 않는다(T-07, 선택).
5. **기존 것을 깨지 않는다.** 기존 스냅샷과 예제 난수 순서가 바뀌면 안 된다.

## 3. 설계

### 3.1 `table_classic`이 무엇인가

출판 관행의 표는 **booktabs** 형태다.

- 가로줄 **세 개만**: 맨 위(굵게), 머리글 아래, 맨 아래(굵게)
- **세로줄 없음**, 칸 배경 없음, 행 교대 음영 없음
- 머리글은 굵게 또는 그대로, 바탕색 없음
- 열 사이는 선이 아니라 **여백**으로 가른다

현재 컴펜디움 표지의 표는 정반대다(짙은 머리글 바탕, 교대 음영, 격자 전체). 그래서 두 프리셋이 필요하다.

### 3.2 스키마에서 반드시 설정으로 뺄 것

| 묶음 | 키 |
|---|---|
| 열 선택 | 어느 열을, 어떤 순서로, 어떤 머리글 문구로 |
| **열별 서식** | 정렬(숫자 오른쪽·문자 왼쪽이 기본), 숫자 서식(소수 자릿수, 천 단위 구분, 유효숫자, 지수 표기 기준), 결측 표시 |
| 열 너비 | 자동(내용 측정) 또는 고정, 줄바꿈 허용 여부, 최대 줄 수 |
| 규칙선 | 세 줄의 두께·색, 그릴지 여부 |
| 타이포 | 머리글 크기, 칸 크기, 글꼴(페이지 프리셋에서 상속) |
| 행 | 행 높이(내용 기반 또는 고정), 상한과 초과 시 동작, 교대 음영(classic은 꺼짐) |
| 부가 | 제목, 각주, 머리글 그룹(여러 열을 묶는 상위 머리글) |

### 3.3 preflight가 공짜로 잡는 것

표에서 실제로 터지는 것은 **글자 잘림**과 **최소 글자 크기**인데 preflight가 이미 둘 다 본다. 손으로 좌표를 놓던 방식에서는 이 검사가 돌지 않았다. 이 계획의 실질적 이득 가운데 가장 큰 항목이다.

## 4. 작업 카드

상태·담당·커밋은 상태 파일에만 적는다. 여기서는 범위와 완성 조건만 적는다.

- **T-01 — 계획과 상태 파일.** 이 문서 + 상태 yaml.
- **T-02 — 코어 렌더러 `table`.** `fa new renderer table`로 시작. SCHEMA(§3.2), 열별 서식, 자동 열 너비, 줄바꿈, 규칙선, 각주. 테스트: 서식이 설정대로 적용되는지, 너비 계산이 내용에 반응하는지, 행 상한 초과 시 경고. 갤러리 예제 1건.
- **T-03 — `styles/table_classic.yaml`.** booktabs 기본값(§3.1). `print`·페이지 프리셋과 겹쳐 쓸 수 있어야 한다.
- **T-04 — 코드 없는 경로.** `plot_type: table` 계약과 ingest 연결. 번들의 CSV를 바꾸고 `fa ingest bundle`만 돌리면 표가 나오는 상태.
- **T-05 — 컴펜디움 표 페이지.** 게이트 G2 통과 후. 스토리라인의 `tables:` 항목을 렌더러로 그려 페이지로 넣는다. 긴 표는 넣지 않고 CSV만 가리킨다(§1 "하지 않는 것"). 쪽번호·목차와 맞물린다.
- **T-06 — 문서.** 갤러리 등재, how-to 한 쪽("표를 그리기", 투고용이 아니라는 경고 포함).
- **T-07 — (선택) 표지 표를 렌더러로.** 지금 코드는 돌아가므로 서두르지 않는다. 안 해도 된다.

## 5. 완성 정의

한 카드는 다음이 모두 있을 때 끝난다(plot catalog §5와 같은 기준).

1. 렌더러 + SCHEMA, 하드코딩 lint 통과
2. 테스트(단위 + 스냅샷), CI green
3. 갤러리 예제와 문서 등재
4. `plot_type` 계약과 ingest 연결(T-04 범위)
5. 기존 스냅샷 불변
