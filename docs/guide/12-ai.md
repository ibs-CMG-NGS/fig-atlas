# 12. AI와 함께 일하기

> **이런 적 있으시죠?** AI에게 그림을 고쳐 달라고 했더니 결과는 그럴듯했는데, 무엇을 어떻게 바꿨는지 알 수 없었다. 다음에 같은 부탁을 했더니 다르게 고쳤다.

**핵심:** fig-atlas에서 AI는 **사람과 같은 명령**을 대신 실행합니다. 파일을 바꾸기 전에 무엇이 바뀌는지 보여 주고, 연구자가 확인한 뒤에 진행합니다. 그래서 어떤 AI를 쓰든 결과가 같고, 무엇이 바뀌었는지 항상 알 수 있습니다.

## AI가 일하는 방식

- AI 도우미(Claude Code, Gemini CLI, Antigravity, opencode, Cursor, Codex 등)는 fig-atlas의 **도구 목록**을 연결받아 씁니다([연결 방법](../howto/ai_agents.md)). 프로젝트 만들기, 번들 붙이기, 빌드, 그림 보기, 승격·은퇴 같은 일이 모두 도구로 있습니다.
- 파일을 바꾸는 도구는 **처음 부르면 미리보기(무엇이 바뀌는지)만** 돌려줍니다. AI는 그것을 보여 주고, 연구자가 동의하면 실제로 적용합니다.
- AI는 저장소의 규칙 파일([`AGENTS.md`](../../AGENTS.md))을 읽고 따릅니다. 원본 데이터 읽기만 하기, 설정 주석 지우지 않기, 색·디자인 변경 전에 묻기 등이 들어 있습니다(13장).
- 같은 작업을 사람이 직접 명령으로, opencode가, Antigravity가 각각 해 봤을 때 **결과 파일이 바이트 하나까지 같았습니다**(2026-10-08 시험).

## 맡겨도 되는 일과 직접 판단할 일

| AI에게 맡겨도 되는 일 | 연구자가 직접 판단할 일 |
|---|---|
| 프로젝트 만들기, 번들 붙이기, 빌드 | 어떤 데이터를 어떤 그림으로 보여 줄지 |
| 설정 값 고치기 (크기, 범위, 배치) | 그림의 의미를 바꾸는 색·디자인 결정 |
| 검사 오류를 설정으로 고치기 | 경고를 그대로 둘지 |
| 결과 요약, 그림 설명 초안 | 그림이 주장하는 내용, 주장 범위 |
| 승격·은퇴 실행, 대응표 갱신 | 어느 그림이 Figure 몇 번이 될지 (스토리라인) |
| 개편 기록의 "무엇이 바뀌었나" 정리 | 개편의 "왜" |
| 새 그림 종류의 초안 만들기 | 그 그림이 원하는 모양인지 확인 |

## 좋은 요청, 아쉬운 요청

| 아쉬운 요청 | 좋은 요청 | 왜 |
|---|---|---|
| "그림 예쁘게 해 줘" | "패널 b 글자를 패널 a와 같은 크기로 맞추고, 범례를 오른쪽 위로 옮겨 줘" | 무엇을 바꿀지가 분명해야 결과를 확인할 수 있습니다. |
| "이 데이터 그려 줘" | "`raw_data/…/volcano_bundle`을 lab 탐색 프로젝트 `lab-acute-1d-de`에 붙여서 빌드해 줘" | 어느 프로젝트에 들어갈지 정해야 이름과 폴더가 맞습니다. |
| "오류 다 고쳐 줘" | "인쇄 전 검사 오류를 설정으로 고쳐 줘. 색이나 디자인을 바꿔야 하면 먼저 물어봐" | AI가 의미 있는 결정을 혼자 내리지 않게 합니다. |
| "숫자 넣어 줘" | "Figure 2 설명의 앵커 개수를 분석에서 기록하는 살아 있는 숫자로 바꿔 줘" | 손으로 적은 숫자는 데이터와 어긋납니다(9장). |

## 새 그림을 들여올 때

번들이 있는지, 직접 짠 그림 코드가 있는지, 원하는 그림의 캡처·스케치만 있는지에 따라 AI가 일하는 순서가 다릅니다(Case A·B·C). 특히 코드 없이 모양만 있을 때(Case C)는 AI가 **그리기 전에 해석안을 먼저 확인받는** 단계가 꼭 있습니다. 자세한 내용은 [5. 그림을 들여오는 세 가지 길](05-entry-paths.md)에 있습니다.

## AI 작업 뒤 확인할 것

- [ ] 미리보기(바뀔 내용)를 보고 동의한 뒤에 적용됐는가
- [ ] 바뀐 것이 설정 파일이고, 원본 데이터(`raw_data/`)는 그대로인가
- [ ] 설정 파일의 설명 주석이 그대로 남아 있는가
- [ ] 인쇄 전 검사 **오류가 0**인가, 경고는 무엇인지 들었는가
- [ ] 그림 설명의 숫자가 살아 있는 숫자인가
- [ ] 논문 그림이라면 스토리라인의 Figure 번호와 프로젝트 이름이 맞는가

> AI는 실수할 수 있습니다. 하지만 이 도구에서는 **AI가 한 일이 모두 설정 파일의 변경으로 남기 때문에**, 무엇이 바뀌었는지 보고 되돌릴 수 있습니다.
