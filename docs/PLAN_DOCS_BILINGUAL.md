## 1. 배경과 목표

문서 사이트(https://ibs-cmg-ngs.github.io/fig-atlas/)의 안내 문서는 한국어로 쓰였고 완성도가 높습니다. 반면 논문·프리프린트·Zenodo DOI로 들어오는 독자는 영어로 읽습니다. 한국어판을 버리지 않고 **영어를 기본으로, 한국어를 두 번째 언어로** 두어 사이트 상단에서 오가게 합니다.

**목표**
- 링크로 들어온 첫 화면이 영어이고, 같은 페이지의 한국어판으로 버튼 하나로 갈 수 있다.
- 두 판이 서로 어긋나지 않게 CI가 구조를 점검한다.
- 튜토리얼은 두 언어 모두 "문서대로 하면 같은 결과"가 보장된다.

**하지 않는 것**
- 자동 생성 레퍼런스(명령, 파이썬, 설정 키, 갤러리, 렌더러 사용처)의 한국어판. 코드에서 영어로 생성되며, 한국어 사이트에서도 영어 페이지를 그대로 보여 준다.
- `AGENTS.md`, `.agents/skills/` 번역. 에이전트용 규칙이라 사이트 범위 밖이다(필요하면 별도 계획).
- 기계 번역 결과를 검토 없이 싣는 것.

## 2. 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 기본 언어 | 영어 (`/`) | 논문·Zenodo 독자. 원고 용어와 일치 |
| 두 번째 언어 | 한국어 (`/ko/`) | 연구실 구성원. 기존 문서 보존 |
| 정본 | 영어. 내용을 바꿀 때는 같은 커밋에서 두 판을 함께 고친다 | 어긋남 방지. 한쪽만 고치면 CI가 잡는다(구조 차이) |
| 파일 구조 | 같은 폴더에 `page.md`(영어) + `page.ko.md`(한국어) | `mkdocs-static-i18n`의 suffix 방식. 링크·그림 경로를 두 판이 공유 |
| 그림 | 두 판이 같은 파일(`docs/tutorials/img/` 등)을 쓴다. 대체 텍스트만 번역 | 그림 속 글자는 이미 영어 |
| 메뉴 | `mkdocs.yml`의 nav 제목은 영어, 한국어 제목은 `nav_translations` | 메뉴 한 벌로 관리 |

**기술 검증 (2026-10-13, 임시 폴더에서)**: `mkdocs-static-i18n` 1.3.1 + mkdocs 1.6 + material 9.5, 이 저장소의 `strict: true`, 한글 앵커 slugify, 링크 재작성 훅(`scripts/mkdocs_hooks.py`) 그대로 빌드 경고 0. 영어 `/`, 한국어 `/ko/`, 언어 전환(`hreflang` en·ko)과 번역 안 된 페이지의 대체 표시가 동작함을 확인.

## 4. 번역 원칙

**문체**: 생물학자를 위한 쉬운 영어. 짧은 문장, 능동태, 한 문장에 한 가지. 한국어판의 구조(절, 표, 예시, 💬/⌨ 표시)를 그대로 따른다. 의역은 하되 내용을 더하거나 빼지 않는다. 한국어판에서 발견한 오류는 두 판 모두 고친다.

**그대로 두는 것**: 명령, 코드, 파일 이름, config 키, 출력 예시, 예시 데이터, 링크 대상.

**용어 대조표 (Phase 1 검토 반영, 2026-10-14)**: 원고(`docs/paper/manuscript.md`)의 용어와 맞춘다.

|---|---|
| 이런 적 있으시죠? / 핵심: | Has this ever happened to you? / The key idea: |
| 연구자 안내서 | Guide for researchers |
| 숫자·통계·이미지의 정직성 | Transparency in numbers, statistics and images |
| 데이터 번들 / 번들 | data bundle / bundle |

| 그림 명세 / 그림 설명 파일 | figure spec |
| 인쇄 전 검사 | preflight |
| 출처 기록 | provenance record |
| 살아있는 숫자 | live numbers |
| 최종 크기 렌더링 | final-size rendering |
| 패널 태그 | panel tag |

## 5. 동기화 장치 (Phase 0에서 만든다)

1. **짝 점검** (`tests/test_docs_i18n.py`, CI): `page.ko.md`마다 `page.md`가 있고, 두 판의 다음이 같아야 한다 — 제목 수준의 순서(`#`, `##`, ...), 코드 블록 수와 내용, 그림 수와 경로, 표 수, 링크 대상(앵커 제외: 한글 제목의 앵커는 판마다 다르다). 다르면 실패하고 어느 쪽이 무엇을 빠뜨렸는지 보고한다.
2. **튜토리얼 실행 단계 동일성**: 두 판의 `<!-- run -->`·`<!-- replace: -->`·`<!-- file: -->` 블록이 글자 그대로 같아야 한다. 실행은 영어판으로 한다(`tests/test_tutorials.py`). 그래서 두 언어 모두 문서대로 하면 같은 결과가 나온다.
3. **번역 대기 목록** (`docs/i18n_pending.txt`): 아직 영어판이 없는 페이지. 이 페이지들은 전환 기간 동안 한국어 내용 그대로 기본 언어 자리(`page.md`)에 남는다. 목록에 없는 한국어 페이지가 생기면(새 페이지를 한국어로만 쓴 경우) CI가 실패한다. Phase 5에서 목록이 빈다.
4. **운영 규칙**: `AGENTS.md`에 "문서를 고치면 같은 커밋에서 영어판과 한국어판을 함께 고친다"를 넣는다. AI 도우미도 이 규칙을 따른다.

한계: 구조는 맞춰도 문장 내용이 같은지는 기계가 보장하지 못한다. 그래서 Phase마다 연구자가 몇 쪽을 골라 읽는다.

## 6. Phase별 계획과 완료 기준

### Phase 0 — 기반
- `mkdocs.yml`: `i18n` 플러그인(영어 기본, 한국어 `/ko/`), 테마 언어 영어, nav 제목 영어 + 한국어 `nav_translations`.
- 의존성: `pyproject.toml`의 `docs` extra와 `docs.yml`/`ci.yml`에 `mkdocs-static-i18n`.
- 짝 점검·대기 목록 테스트, `AGENTS.md` 규칙.
- 이 시점에는 모든 한국어 페이지가 대기 목록에 있고, 사이트는 지금과 같은 내용을 보여 준다(메뉴 제목만 영어).

**완료 기준**: `mkdocs build --strict` 경고 0, 테스트 통과, 사이트에 언어 전환 버튼, 기존 페이지 모두 열림.

### Phase 1 — 첫 화면과 가이드 앞부분 (게이트 G1)
- `index`, 가이드 00–02 영어판 작성, 한국어판은 `.ko.md`로 이름만 바꿈.
- 용어 대조표 확정안.

**완료 기준**: 연구자가 영어판 4쪽과 용어 대조표를 읽고 문체·용어를 승인. 이후 Phase는 이 문체로 진행.

### Phase 2 — 가이드 나머지
- 가이드 03–13, 부록 4, `_template`.
- 가이드 안의 앵커 링크(예: 다른 장의 특정 절)는 영어판에서는 영어 제목의 앵커로 바꾼다.

**완료 기준**: 짝 점검 통과, 사이트에서 두 언어로 가이드 전체가 이어짐(이전/다음 링크 포함), 연구자 표본 검토 2쪽.

### Phase 3 — 튜토리얼과 How-to
- 튜토리얼 5, How-to 3. 실행 단계 블록은 그대로 두고 설명만 번역.
- 그림 대체 텍스트 번역. 튜토리얼 그림 생성(`fa reference`)은 영어판 기준으로 동작하도록 확인.

**완료 기준**: `tests/test_tutorials.py`가 영어판으로 통과, 실행 단계 동일성 통과, 연구자 표본 검토 1쪽(첫 그림 튜토리얼 권장).

### Phase 4 — 계약서와 설계 결정
- 계약서 4, ADR README와 0001–0005.
- **ADR 0006 "문서는 영어가 정본, 한국어를 함께 둔다"** 신설(두 언어).

**완료 기준**: 짝 점검 통과, `fa bundle contracts`가 가리키는 계약서 링크가 두 언어에서 열림.

### Phase 5 — 마무리
- `docs/i18n_pending.txt` 비움(테스트가 빈 목록을 확인).
- README의 문서 링크, CHANGELOG, `site_description` 정리.
- 사이트 점검: 언어 전환이 같은 페이지로 가는지, 검색이 두 언어에서 동작하는지, 모바일 폭.
- 로드맵 Phase 8 항목 갱신.

**완료 기준**: 대기 목록 0, CI 녹색, 연구자 최종 확인.
